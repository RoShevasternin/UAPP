# Сторінки-патчі UAPP

З 01.10.2026 зміни коду в UAPP ідуть через **сторінку-патч на claude.ai**. Система
перенесена з Orbit Dash (`Game Orbit Dash PRIVATE/Orbit Dash/docs/patches/`).
Claude не править файли ігор, поки VELDAN не обрав на сторінці, хто що вставляє.

## Як це працює

1. **Лабораторія.** Claude копіює потрібні ігри в scratchpad, зберігаючи шляхи від
   кореня UAPP (`<scratchpad>/labNN/UAPP/april_may/Game T5/RBX Boss/…`). Усі зміни
   робляться там: збірка debug + release, перевірка на емуляторі чи девайсі.
2. **Сторінка.** `_page/build.py` рахує різницю «проєкт ↔ лабораторія» і робить кроки
   «було / стало»: ДОДАТИ, ЗАМІНИТИ, ВИДАЛИТИ, НОВИЙ ФАЙЛ, ВИДАЛИТИ ФАЙЛ. Кожна зміна
   має id `файл.зміна` (наприклад, `7.3`). Файли групуються за грою, бо один патч може
   зачіпати кілька ігор: еталон і апку, на якій зараз працюємо.
3. **Вибір.** VELDAN на сторінці обирає для кожної зміни **«Вставив сам»** або
   **«Вставити автоматично»** і тисне «Готово — надіслати Claude». Сторінка зберігає
   вибір у собі (`state` у `<script id="patch-data">`) через можливість `artifact`.
4. **Сигнал у чат.** Сповіщення сесію не будить. Після «Готово» сторінка дає кнопку
   «Скопіювати для чату», і в чат приходить рядок
   `Патч NN · Готово · сам X · авто Y`. Цей рядок означає: прочитай сторінку NN і зроби.
5. **Вставка.** Claude читає сторінку (`Artifact action:"read"`), бере `state`, далі:
   - `auto` — вносить зміну дослівно з даних сторінки. Для заміни перевіряє, що `old`
     зустрічається у файлі рівно один раз. НОВИЙ ФАЙЛ — Write, ВИДАЛИТИ ФАЙЛ — rm.
   - `manual` — перевіряє, що `new` уже є у файлі, і пише «знайдено / не знайдено».
   Обрав «авто» — Claude вставляє без додаткових питань.
6. **Перевірка.** Збірка (`sh ./gradlew :app:assembleDebug`), установка на девайс,
   скріншот, лог. Звіряння з лабораторією: `diff -rq`.
7. **Позначка результату.** `_page/mark.py pages/NN.html '<state-json>'` міняє лише `state`.
   Тут треба проставити `result` на кожну зміну і загальний `{ok, at, note}`. Потім
   публікація того самого файлу на той самий URL. З іншої сесії публікувати треба з
   `url` зі списку нижче, інакше вийде нова сторінка.
8. **Git.** Запис `NN-*.md`, `pages/NN.*` і пам'ять закомітити й запушити.

## Пастки

- **Сторінку збирати до вставки.** Якщо код уже в проєкті, різниця нульова, і сторінка
  вийде без кроків. Порядок такий: лабораторія → збірка → `build.py` → публікація →
  вибір → вставка. Позначати результат лише через `mark.py`, не перезбирати.
- `build.py` запускати **з `docs/patches/`**: `summary_md` у спеці відносний до цієї теки.
- Лабораторія живе в scratchpad і зникає разом із сесією. Кроки при цьому лишаються в
  `pages/NN.html` і на сторінці, тож вставляти можна з будь-якої наступної сесії.
- Markdown у поясненні мінімальний: заголовки `##`, абзаци, списки `- `, таблиці, блоки
  ```` ``` ````, `код`, **жирний**. Іншого `_page/build.py` не розуміє.
- Спершу еталон, потім бекпорт (див. `CLAUDE.md`). Апка, на якій VELDAN працює зараз,
  може йти в одному патчі з еталоном.

## Команди

```
cd /Users/admin/Apps/UAPP/docs/patches
python3 _page/build.py pages/NN.spec.json pages/NN.html
python3 _page/mark.py pages/NN.html '{"submitted":"…","hunks":{"1.1":{"choice":"auto","result":{"ok":true,"note":"вставлено"}}},"result":{"ok":true,"at":"…","note":"збірка пройшла"}}'
```

Публікація: `Artifact` з `file_path` = `pages/NN.html`, `capabilities: {"artifact": {}}`,
icon `code`.
