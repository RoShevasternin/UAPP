Meta SDK в UAPP

Як додати Meta (Facebook) SDK у гру парку поруч із TikTok: сім змін у коді, формат блоку на сервері, звідки брати ключі й як перевірити, що Meta приймає події.

Підготував VELDAN. Зразок, на якому все перевірено: T5 RBX Boss (debug і release на реальному девайсі).

  • facebook-core 18.3.0
  • лише App Events
  • ключі тільки з сервера
  • без ключів — тихо пропускає

Як це працює

Meta SDK лише рахує встановлення, запуски й одну нашу подію, щоб реклама в Meta Ads бачила результат. Facebook Login і Share не підключаємо. Ключі в апку не зашиваємо: вони приходять із нашого конфіг-сервера так само, як ключі TikTok.

Сервер

Віддає блок meta з app_id і client_token поруч із tiktok.

Запуск SDK

З кешованого конфігу ще в App.onCreate. Найперший запуск — у MainActivity після свіжого конфігу.

Події

Встановлення й запуски — автоматично. На головний екран — fb_mobile_achievement_unlocked.

Блоку meta немає, або одне з полів порожнє: у лозі один рядок Meta config missing/invalid — skip init, і гра працює далі, як із TikTok. Помилок і крашів немає.

Перед початком

Інструкція для апок, мігрованих за еталоном (є businesModule і TikTok). Переконайся, що в проєкті є все з цього списку. Якщо чогось бракує, спершу мігруй апку за процедурою.

  • Провайдери аналітики і AnalyticsManager зі списком providersservices/analytics/
  • RemoteConfigModel з полем tiktokadsmodule/RemoteConfigModel.kt
  • initTikTok(model) у двох місцях отримання конфігуMainActivity.kt
  • initAdPref(), що кладе кешований конфіг в AdConfig.remoteConfigApp.kt
  • Правило R8, що зберігає класи adsmodule для Gsonapp/proguard-rules.pro

// Meta (Facebook)
// ------------------------------------------------------------------------
data class MetaConfig(
    @SerializedName("app_id")       val appId      : String? = null,
    @SerializedName("client_token") val clientToken: String? = null,
) {
    val isValid: Boolean
        get() = !appId.isNullOrBlank() && !clientToken.isNullOrBlank()
}

НОВИЙ ФАЙЛMetaManager

Запускає SDK один раз. До запуску прапорець isReady вимкнений, і події не відправляються.

app/src/main/java/{{PATH}}/services/meta/MetaManager.kt
package {{PKG}}.services.meta

import android.app.Application
import com.facebook.FacebookSdk
import com.facebook.LoggingBehavior
import com.facebook.appevents.AppEventsLogger
import {{PKG}}.BuildConfig
import {{PKG}}.util.OneTime
import {{PKG}}.util.log

// Meta SDK — лише App Events. App ID і Client Token приходять із нашого сервера
// (блок "meta" конфігу), тому в маніфесті їх немає: автостарт Meta на початку процесу
// тихо пропускається, а справжній старт — тут, щойно прийшов конфіг.
object MetaManager {

    private val once = OneTime()

    // true після успішного старту. До нього AppEventsLogger створювати не можна — кине виняток
    @Volatile
    var isReady = false
        private set

    fun initialize(app: Application, appId: String, clientToken: String) {
        once.use {
            runCatching {
                FacebookSdk.setApplicationId(appId)
                FacebookSdk.setClientToken(clientToken)
                if (BuildConfig.DEBUG) {
                    FacebookSdk.setIsDebugEnabled(true)
                    FacebookSdk.addLoggingBehavior(LoggingBehavior.APP_EVENTS)
                }
                @Suppress("DEPRECATION")
                FacebookSdk.sdkInitialize(app)
                FacebookSdk.setAutoInitEnabled(true)
                FacebookSdk.fullyInitialize()

                // встановлення й запуски — на них тримається атрибуція реклами Meta
                AppEventsLogger.activateApp(app)

                isReady = true
                log("Meta SDK initialized SUCCESSFULLY, appId=$appId")
            }.onFailure {
                log("Meta SDK FAILED: $it")
            }
        }
    }
}

НОВИЙ ФАЙЛMetaAnalyticsProvider

Повторює TikTokAnalyticsProvider: ті самі місця в грі, лише події Meta. Якщо в апці провайдер TikTok шле ще щось, додай відповідну подію Meta з AppEventsConstants.

app/src/main/java/{{PATH}}/services/analytics/MetaAnalyticsProvider.kt
package {{PKG}}.services.analytics

import com.facebook.FacebookSdk
import com.facebook.appevents.AppEventsConstants
import com.facebook.appevents.AppEventsLogger
import {{PKG}}.adsmodule.UserType
import {{PKG}}.services.meta.MetaManager

// Дзеркало TikTokAnalyticsProvider: ті самі місця в грі → стандартні події Meta.
// Поки SDK не стартував (немає блоку "meta" в конфігу) — подія мовчки пропускається.
class MetaAnalyticsProvider : AnalyticsProvider {

    // Створюється при першій події, коли SDK вже працює
    private val logger by lazy { AppEventsLogger.newLogger(FacebookSdk.getApplicationContext()) }

    override fun openHomeScreen() = track(AppEventsConstants.EVENT_NAME_UNLOCKED_ACHIEVEMENT)
    override fun userType(userType: UserType, referrer: String) {}

    override fun hasClick_ORGtoPAID(referrer: String, irClickTime: String) {}

    // ------------------------------------------------------------------------
    // Helper
    // ------------------------------------------------------------------------
    private fun track(event: String) {
        if (MetaManager.isReady) logger.logEvent(event)
    }
}

ДОДАТИРанній старт у App

Імпорт, виклик одразу після initAdPref() і функція поруч з іншими init…. Так SDK стартує до першого екрана, і Meta бачить початок сесії.

app/src/main/java/{{PATH}}/App.kt · імпорт
import {{PKG}}.services.meta.MetaManager
App.kt · onCreate(), одразу після initAdPref()
        // ── 1a. Meta SDK з кешованого конфігу ─────────────────────────────────
        // Старт до першого екрана — інакше Meta не бачить запуск сесії.
        // Найперший запуск (кешу ще немає) — старт у MainActivity після конфігу
        initMetaFromCache()
App.kt · після initAdPref()
    private fun initMetaFromCache() {
        val meta = AdConfig.remoteConfig?.meta ?: return
        if (meta.isValid) MetaManager.initialize(this, meta.appId!!, meta.clientToken!!)
    }

Що віддає сервер

Серверна команда додає блок у картку кожної апки, поруч із tiktok. Назви полів мають збігатися дослівно: інакше апка мовчки пропустить Meta.

відповідь конфіг-сервера
"meta": {
  "app_id": "123456789012345",
  "client_token": "0123456789abcdef0123456789abcdef"
}

Значення в кожної гри свої. App Secret у конфіг не кладемо ніколи: апці він не потрібен, а Meta забороняє зашивати його в застосунок.

Ключі в кабінеті Meta

Робить той, хто веде рекламний акаунт. На кожну гру — окремий застосунок у Meta.

КрокЩо зробити
1. Створитиdevelopers.facebook.com → My Apps → Create app. Use case: фільтр Ads and monetization → Create & manage app ads with Meta Ads Manager. Варіант «Other» не брати: Meta його прибирає. Facebook Login не потрібен.
2. БізнесBusiness portfolio — бізнес-акаунт, з якого підуть кампанії.
3. App IDApp settings → Basic (також угорі кабінету).
4. Client TokenApp settings → Advanced → Security → Client token.
5. AndroidApp settings → Basic → Add platform → Android. Package name: {{PKG}}. Class name: {{PKG}}.{{ACT}}. Key hashes лишити порожніми (вони лише для Facebook Login). Заповнити Privacy Policy URL → Save changes.
6. СерверApp ID і Client Token передати серверній команді для блоку meta цієї апки.
7. Перед рекламоюApp Mode → Live. Play Console → Data safety: дописати дані, які збирає Meta SDK (рекламний ID, взаємодія з апкою).

Перевірка

Зібрати й запустити debug і release. Release без підпису на телефон не стане, тож для тесту підпиши його debug-ключем:

термінал, з теки проєкту
sh ./gradlew :app:assembleDebug :app:assembleRelease
BT=$(ls -d ~/Library/Android/sdk/build-tools/* | sort -V | tail -1)
"$BT/zipalign" -f -p 4 app/build/outputs/apk/release/app-release-unsigned.apk /tmp/aligned.apk
"$BT/apksigner" sign --ks ~/.android/debug.keystore --ks-pass pass:android --key-pass pass:android --ks-key-alias androiddebugkey --out /tmp/release-test.apk /tmp/aligned.apk
adb install -r /tmp/release-test.apk
СитуаціяЩо має бути в logcat (debug)
На старті, завждиFacebookInitProvider: Failed to auto initialize — нормально: Meta пробує стартувати сама, але ключів у маніфесті немає.
Сервер без блоку metaMeta config missing/invalid — skip init, далі TikTok SDK initialized SUCCESSFULLY. Подій у Meta немає.
Сервер віддає ключіMeta SDK initialized SUCCESSFULLY, appId=…, потім FacebookSDK.AppEvents: MOBILE_INSTALL_EVENT, fb_mobile_activate_app і Result: Success.
Неправильні ключіResult: Failed, errorCode: 190, OAuthException. Перевір App ID і Client Token у конфігу.

У кабінеті Meta: Events Manager → Набори даних → застосунок. Події видно у вкладці «Тестування подій» одразу. «Огляд» оновлюється із затримкою до кількох годин, і період угорі має включати сьогоднішню дату.

Пастки

  • Банер «Оновіть Facebook SDK» в Events Manager стосується iOS (SKAdNetwork). Для Android не потрібен, якщо стоїть 18.3.0 або новіша.
  • Ключі не кладемо в маніфест, strings.xml чи local.properties. Рішення VELDAN: ключі приходять тільки з сервера, тестових у проєкті немає.
  • Найперший запуск після встановлення. SDK стартує вже після відкриття екрана, тож початок цієї сесії Meta не бачить. Встановлення при цьому зараховується, а з другого запуску старт іде з кешу до першого екрана.
  • Два initTikTok(model) у MainActivity. Якщо initMeta додати лише в один, на запасному Firebase RC Meta не стартує.
  • MIUI/HyperOS вбиває фоновий процес гри, поки відкритий лендінг у Chrome. У лозі це Process … has died без FATAL, і це не краш.
  • Тестовий застосунок у Meta на особистому акаунті після перевірки видаляємо (My Apps), щоб не було двох застосунків з одним пакетом.
