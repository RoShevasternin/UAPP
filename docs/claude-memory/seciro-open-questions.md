**28.11.2026, build 24 — частину питань вирішили ми (правило [[seciro-android-decisions-ours]]):** захист сайтів — через VPN (інструкцію Safari прибираємо; Hide Cookie Prompts прибираємо, 4 фільтри); Protection Review — ті самі 4 перевірки (Web Protection · Android update · Screen lock · Biometric unlock), оновлення зелене до 4 місяців, телефон без біометрії — рядок ховаємо; замок → одразу пейвол; Copied! лише на Android ≤12; Language — системний вибір мови; логотип витоку — перша літера; Wi-Fi з QR — лише копіюємо пароль. Віталію лишились продукт / сервер: оплата (дія), Fastest, фільтри окремо на сервері, хто перевіряє QR, Alerts, Get help/Contact, пуші, логотип і «700M» з сервера, кнопки Breach, довжина пароля, мови.

Seciro для Android: невирішене на **27.11.2026** (третя редакція кіта Віталія: https://claude.ai/artifact/Hj3FPMn8KawTvA1gCBkAUa).
Коли питають «чого нам ще треба» — відповідати за цим списком і звірити з документацією в адмінці (розділ «Seciro for Android» міг змінитись).
Пов'язане: [[vpn-app-new-type]], [[seciro-build-by-design]], [[seciro-kit-style]].

**Картки кіта (Влад → Віталій); відповідь у чаті номером і варіантом:**
1. billing — хто що робить: Влад — продукти в Play Console і JSON-ключ сервісного акаунта Google Play для RevenueCat → Віталію; Віталій — Android-проєкт в окремому акаунті RevenueCat, SDK-ключ (`goog_…`) → Владу; сервер — прийом покупок Play («в розробці»).
2. vpn — чекаємо сервер: протокол (найімовірніше IKEv2 → мінімум Android 11, зараз 10); поки `403 no_access`. Вирішувати нічого — лише повідомити Влада.
3. fastest — «Fastest Connection»: A сервер вибирає / B перша локація списку / C як в iOS. Апка сама не виміряє: у списку локацій немає адрес.
4. testacc (виділене «Тестування») — рідкісні екрани (підписка закінчилась, оплата не пройшла, оновити апку): A перемикати тестовий акаунт на прохання / B окремі акаунти / C ні (підставні відповіді сервера в тестовій збірці).
5. web — які фільтри лишаються (Hide Cookie Prompts через VPN надійно не зробити); підказка «увімкніть VPN» так/ні; інструкцію Safari прибрати так/ні.
6. qrcheck — хто дає вердикт safe/warning/unsafe: A сервер Seciro / B сторонній сервіс через сервер / C як в iOS.
7. extras — Get help і Contact: A пошта / B чат / C сайт / D прибрати; Alerts: A список / B прибрати; пуші: A сервер (Firebase — хто створює) / B лише апка / C без пушів.
8. review — Protection Review: ті самі 4 пункти, що в дизайні (Web Protection через VPN, оновлення Android, блокування екрана, відбиток) — підходить?
9. breach — логотипи (A сервер / B іконка сайту за доменом / C перша літера), «700M accounts» (A сервер / B прибрати), кнопки Change Password і Beware of Scam Calls (A сайт / B порада / C прибрати).
10. password — межі довжини: A 8–20 (за положенням повзунка у Figma — так у прототипі) / B 8–32 / C 12–64 / D як в iOS.

**Ще в розробці на сервері (не питаємо):** ліміт пристроїв iPhone + Android (поки Android місця не займає: `seatLimit: null`,
екрана «пристрій вийшов» на Android зараз не буває); вхід після покупки на сайті (Install Referrer); сторінка видалення акаунта на сайті.

**Знято 27.11:** Storage «Clean up storage» — як у Figma (відкриває вибір файлів); хто робить RevenueCat (Віталій); формат скрінів
планшета (зробить дизайнер); ліміти для тестів — з кіта прибрано: ліміт Breach Check навіть потрібен, щоб перевірити екран ліміту,
а ліміт кодів не заважає, якщо 6 цифр тестового акаунта — постійний код (припущення; код у репо не писати).

**Не питання:** задачі Віталія — у ClickUp, доступ VELDAN дасть, коли буде треба. Екрани, яких немає у Figma, — у кіті дизайнера
(https://claude.ai/artifact/PCBWKfSi31ZxWoQc3hFeHL). Мови апки тощо не вигадуємо ([[seciro-build-by-design]]).
