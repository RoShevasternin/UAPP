Інтерактивні звіти, дослідження й демо за замовчуванням робимо як артефакт на claude.ai: публікуємо й віддаємо посилання.

Файл кладемо в репо лише тоді, коли користувач скаже, що це треба зберегти.

- **Куди:** окрема тека `docs/research/<тема>-дд-мм-рррр/`, всередині `index.html` плюс `data/` із сирими даними. Назва теки англійською. Приклад: `docs/research/sms-29-09-2026/`.
- **Брифи окремо.** Постановка задач розробникам (бриф, «чим мають зайнятись») — це не результат аналізу, тому йде в `docs/research/briefs/<ВИКОНАВЕЦЬ>-<тема>-дд-мм-рррр/` (ім'я розробника великими літерами — так назвав сам користувач): `brief.md` (читається на GitHub) + `index.html` (та сама сторінка для браузера). Обидва — експорт із Claude Docs, у шапці посилання на живу версію. Приклад: `docs/research/briefs/TARAS-reward-ads-29-09-2026/`. Рішення користувача від 30.09.2026.
- **Збереження HTML-артефакту.** Файл артефакту не має `<!doctype>` і `<meta charset>` (їх додає обгортка claude.ai), тож при збереженні в репо дописувати зверху `<!doctype html>`, `<meta charset="utf-8">`, viewport і коментар із посиланням на живу версію — інакше з диска кирилиця ламається. Для інтерактивного брифу — лише `index.html`, без `brief.md` (md був тільки для експорту з Claude Docs). Приклад: `briefs/NASUF-tiktok-30-09-2026/`.
- **Git:** тека не ігнорується і йде в git разом з усім UAPP. Див. [[uapp-git-backup-public-repo]].

**Why:** Користувач так сказав: «давай робити claude.ai, але коли я скажу, що це треба зберегти, то окремою папкою з HTML будемо класти». Посилання на claude.ai зручне, щоб показати колегам. Репо — це бекап, а не смітник чернеток.

**How to apply:**
- Не копіювати HTML у UAPP за власною ініціативою.
- Після збереження оновлювати і теку, і артефакт за тим самим посиланням, щоб вони не розходилися.
